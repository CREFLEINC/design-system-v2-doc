# 문서 정보 5개 항목 표준화 설계

*2026-08-03 · GitHub Issue #10*

## 목적

`crefle-doc`으로 문서를 작성할 때 문서의 출처·시점·유효성·배포 범위를 추정하지 않게 한다.
보고서, 연구노트, 회의록, 발표 덱은 같은 문서 정보 5개 항목을 제공하고, 작성 스킬은 본문을
채우기 전에 사용자 확인을 받는다.

## 표준 문서 정보

네 템플릿은 다음 항목을 같은 순서로 제공한다.

| 순서 | 항목 | 값 규칙 |
|---:|---|---|
| 1 | 작성자 | 사용자에게 직접 확인한다 |
| 2 | 작성일 | 시스템 날짜를 후보로 제안할 수 있으나 사용자 확인 후 확정한다 |
| 3 | 작성시간 | 시스템 시각을 후보로 제안할 수 있으나 사용자 확인 후 확정한다. 별도 행에 24시간제 `HH:mm`으로 쓴다 |
| 4 | 문서 버전 | 사용자에게 직접 확인한다 |
| 5 | 열람 대상 | 사용자에게 직접 확인한다 |

열람 대상은 `사내 한정`, `프로젝트 관련자`, `고객사 제출`, `대외 공개`를 권장
선택지로 제시한다. 어느 것도 맞지 않으면 자유 서술을 받는다. 스킬은 선택지를 임의로 고르지 않는다.

## 사용자 확인 흐름

`SKILL.md`의 템플릿 선택과 번들 복사 다음, 내용 작성보다 앞에 **문서 정보 확인** 단계를 둔다.

1. 작성자, 문서 버전, 열람 대상을 질문한다.
2. 작성일과 작성시간은 현재 시스템 값을 후보로 제시할 수 있다.
3. 다섯 항목 모두 사용자 답변 또는 명시적 확인을 받은 뒤 템플릿에 반영한다.
4. 확인되지 않은 값은 추측·유추·관성적 기본값으로 채우지 않는다.
5. 답을 받지 못하면 눈에 띄는 placeholder를 유지하거나 문서 완성을 보류한다.

이 규칙은 기존 자산·색·인라인 스타일 관련 금지 규칙과 같은 강도로 기술한다. 특히 현재 날짜,
`v1.0`, 대화에서 추정한 작성자, 문서 성격에서 추정한 열람 대상을 확정값처럼 쓰지 않는다.

## 템플릿 구조

### 보고서·연구노트·회의록

기존 표 구조를 유지하면서 표준 문서 정보 5개 행을 넣는다. 기존 `버전`은 `문서 버전`으로,
`대상`은 `열람 대상`으로 이름을 통일한다.

연구노트의 `기간`·`상태`와 회의록의 `일시`·`장소`는 문서 자체가 아니라 문서가 다루는
대상의 정보다. 이 항목들은 표준 문서 정보와 분리된 별도 표로 유지한다.

### 발표 덱

기존 타이틀 슬라이드의 캡슐 두 개를 작은 문서 정보 표로 교체한다. 표에는 다른 템플릿과 동일한
항목과 순서를 사용한다. 어두운 표지에서 제목 위계를 방해하지 않도록 덱 전용 CSS를 최소한으로
추가하고, 표지 하단 영역에 배치한다.

## Placeholder

실제 값처럼 보이는 `이름`, 특정 날짜, `v1.0`, `수신처`는 사용하지 않는다. 각 값 셀은
`[사용자 확인 필요]`라는 눈에 띄는 텍스트를 기본값으로 갖고, 인접 HTML 주석으로
`사용자 확인 전 기입 금지`를 명시한다.

텍스트 placeholder를 두는 이유는 HTML 주석만 사용할 경우 렌더링 결과에서 누락을 알아보기
어렵기 때문이다. 완성 문서에는 이 문자열이 남아 있으면 안 된다.

## 예제

문서 정보 블록을 포함하는 `examples/` 문서는 같은 5개 항목과 순서를 사용한다. 예제는 사용법을
보여주는 완성된 샘플이므로 명시적인 예시 값을 쓸 수 있지만, 해당 값이 예시임을 문맥에서 분명히 한다.
문서 정보 블록이 없는 차트 전용 예제에는 새 블록을 억지로 추가하지 않는다.

## 검증

구현은 테스트 우선으로 진행한다.

1. 정적 검증에 네 템플릿의 항목명·순서와 placeholder를 검사하는 실패 테스트를 추가한다.
2. `SKILL.md`에 내용 작성 전 확인 단계, 추정 금지, 날짜·시간 제안 후 확인, 열람 대상 선택지가
   존재하는지 검사한다.
3. 관련 예제가 표준 5개 항목을 따르는지 검사한다.
4. 최소 구현 후 정적 검증, 단위 테스트, E2E, 빌드 재현성 검사를 포함한 `npm run check`를 실행한다.
5. 덱 타이틀 슬라이드의 문서 정보 표가 화면과 PDF에서 넘치지 않는지 기존 Playwright 검증에
   회귀 단언을 추가한다.

## 오류 및 미완성 처리

- 다섯 항목 중 하나라도 확인되지 않았으면 스킬은 값을 발명하지 않는다.
- 사용자가 답변을 보류하면 placeholder를 유지한 초안임을 명확히 알리거나 문서 완성을 중단한다.
- `[사용자 확인 필요]`가 남은 문서를 완성본으로 보고하지 않는다.
- 고유 메타데이터 표와 표준 문서 정보 표를 합쳐 의미를 흐리지 않는다.

## 범위

포함 범위는 `skills/crefle-doc/SKILL.md`, 템플릿 4종, 관련 예제, 필요한 최소 CSS와 검증
테스트다. 보고서 개정이력, reporter 서버 메타데이터, 자동 메타데이터 추출은 이 이슈에서 다루지 않는다.
